# Mistakes made in specs/

The mistakes made in the acceptance specs, the architecture test and the
gate programs that run them, each with the check that stops it. The
rules every change keeps are in the root `AGENTS.md`. Run the check; do
not trust that you would not make the mistake.

| The mistake | The check |
|---|---|
| A spec matched a list of log lines as one string, and refused the expected compiler error before checking the rest. | Read the client function's return type before choosing a matcher, and assert a returned line's text (`TestRetainedWorkspaceRevalidatesOptionsAndRecoversAfterMalformedSettings`). |
| A spec asked a restarted sandbox's daemon for a build before its port listened. | Reopen the workspace through the client, which waits until the daemon is ready; a retried build never stands in for readiness. |
| A safety spec stayed green from a result the grid had kept, because its action was the same and was not run again. | What must run every time differs in what is run (the run's own words, `TestOfThisRun`), a spec that needs a run asserts its result was `executed`, and it asserts what is so afterwards, not how the worker said no. |
| A spec read origin fetches off a metric that counts cache hits too. | Read where a metric is observed before asserting on it, and prove it with a control that must move it and one that must not. |
| The heaviest spec ran beside the rest, held the grid's slots for minutes, and others passed their deadlines waiting. | `mise run test` runs `./specs/build` after every other package (`TestValidationTasksCoverEveryModule`); when tests time out together, read what the worker finished each minute (`docker logs frontseat-stack`, the stack's one container) before blaming the code, and wait for another checkout's self-build to finish before starting a gate. |
| `mise run check` reached a real grid or container runtime where one was up. | `check` tells its tests it runs with no stack (`FRONTSEAT_TEST_STACK=none`, set by the gate, and on the grid by the catalog files of the Components whose tests need the stack, `spec.frontseat.test.environment`), every test that needs the stack says so first (`testrequired.Stack`; `TestATestThatReachesTheContainerRuntimeSaysItNeedsTheStack`), and the gate points Docker at an address nothing listens at (`TestAGateWithNoStackReachesNoContainerRuntime`). |
| A test of a service asked whoever answered on its port, and passed for a server a person had started there. | Hold the service first: the container the stack names, running, publishing that port and given what it is said to be given (`TestTheStackMakesAWorkspaceWithNothingStartedByHand`). |
| A spec called a use case served by doing its neighbour's: "you get a shell" ran `pwd` with no terminal, and a real shell failed in every sandbox. | A spec does what its name says a person does (`A shell at a terminal opens in the workspace`); a command told to someone as a step is run first as they would run it. |
| Specs that ended a workspace and asked at once for another of the same name were refused, because ending goes on after `DeleteWorkspace` returns. | A spec that ends what it made waits until it is gone (`ended`, `delete` in `specs/sandbox/support_test.go`), and reads a workspace's daemon and sandbox from its state once ready. |
| A required suite skipped when its grid was absent, and the run said SUCCESS with no spec run. | `gate test` with the stack asks that the stack answers before it builds or runs anything, and fails naming it where none does (`TestAGateThatNeedsTheStackFailsWhereNoneAnswers`, its control the same gate with `-no-stack`). It and `gate go-test` tell the tests the stack is required (`FRONTSEAT_TEST_STACK=required`), and a helper of the test support that finds the stack missing says so through `testrequired.Missing`, which fails the test there and skips it only where nothing is said (`TestATestOfTheStackFailsInAGateRunByHandWhereNoStackAnswers`, `TestAGateAgainstTheStackFailsATestWhoseStackIsMissing`): a test or a helper that says `testrequired.Stack` never calls `t.Skip` itself (`TestATestThatReachesTheContainerRuntimeSaysItNeedsTheStack`, its fixtures `TestATestThatSkipsItselfAfterSayingItNeedsTheStackIsFound`). Beneath it, for a test run by go test alone: required infrastructure helpers take `testrequired.TB`, which turns a skip into a failure, `testrequired.Stack`'s alone excepted where the gate runs with no stack: give `Stack` what `TB` returned, never a value that embeds it; prove a missing prerequisite fails beside a control where it is there. |
| A shared fixture kept a finished test's handle, or parallel tests changed the process environment. | `TestMain` owns shared directories and servers, fixtures hold data alone and are rebound to each test, and tests that use `Setenv` run one after another. |
| A failed shared-fixture setup left servers alive, and the next test retried on their state. | Give each attempt its own directory, close everything partial on failure, and publish shared state only after success. |
| A layout checker let skipped fixture imports and broad layer crossings through. | Scan nested modules (`TestArchitectureScanIncludesNestedGoModules`), refuse imports into excluded trees, check the client's real dependency closure, and run allowed and refused controls against the real policy. |
| A rule over source was held by a scan of one spelling, so a test, a renamed import or a second function passed it. | A rule over source is a function of one file, tried on a fixture for each way round it beside what it allows (`TestEveryWayToTheContainerRuntimeIsSeen`); an address a person types is read by its parser. |
| Release specs were written for use cases not built and skipped, 72 of them, and `AGENTS.md` cited their file as what held the release rules. | A requirement that is not built is in its design, not in the test binary: no Go test skips itself whatever it is given, at any place in its body or a subtest's (`TestNoTestIsSkippedOutright`, its fixtures each way round in `TestATestSkippedOutrightIsFound`); a Rust test marked `#[ignore]` is not checked, and `AGENTS.md` cites the specs that run, by name. |
| A spec was satisfied by a refusal its own helper made, a copy of the command line's, so the code a person runs was never asked. | A spec's helper refuses nothing: the spec asserts the code of the refusal the server gave (`TestTwoRepositoriesOfOneNameAreNotOneWorkspaceTheSecondIsRefusedAndTakesANameOfItsOwn`), and what the command line adds is proven where it is written. |
| A test of the gate let a gate it ran inside itself print `FAIL` to the terminal, and every log carried a failure that did not happen. | The gate prints through `said` and `complained`, and a test running a gate inside itself keeps what it prints (`quietly`) unless the outcome was not the one wanted. |
| Tests ran git plainly with this machine's settings: macOS's credential helper kept every credential a test presented to `127.0.0.1` (729 in one keychain, counted by `security dump-keychain`) and answered a later test at a reused port with an earlier one's, so a control that waited for git to ask for a password failed now and then under load. | The gate gives what it runs none of this machine's git settings (`GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL`, and empty `core.excludesFile` and `core.attributesFile` in place of a person's own beneath `XDG_CONFIG_HOME`; `TestWhatAGateRunsReadsNoneOfThisMachinesGitSettings`). A test that fails only under load is reproduced under load (several copies at once) before anything is said of why. |
| Tests were named for the occasion they were written on (`TestReview…`, `…POC…`) and passed the rule, which held only files' names. | No word of a Go test's name is an occasion's, nor several of one, nor one that a capital or a number is joined to (`TestATestIsNamedForItsSubject`, its control `TestATestNamedForAnOccasionIsFound`). Not held: a subtest's name, a Rust test's name, and a file named only for its tests holding something (`held_test.go`). |
