# Buf plugin

The Rust plugin uses the shared SDK for strict YAML, source tracking, errors,
options and the plugin ABI. `manifest.rs` reads Buf's native configuration; `actions.rs`
declares worker actions; `plugin.rs` implements discovery. The common real-Wasm
conformance harness uses independent fixtures under `testdata/`.

Supported: Buf v2 workspaces with repository-local modules, `buf lint`, and
`buf generate` with pinned local `protoc-gen-go` and `protoc-gen-connect-go`.
Every template in the workspace is generated by an action of its own, named
from its file: `buf.gen.yaml` by `generate`, `buf.gen.<name>.yaml` by
`generate-<name>` (`buf.gen.sdk.yaml` by `generate-sdk`); a `<name>` is
lower-case letters, digits and dashes, and any other is refused.
Native managed mode and generator options are passed to Buf. Generation inputs
must be local directories; output archives and built-ins are refused
(`invalid-manifest`). Valid and not built yet, and refused `UNIMPLEMENTED` by
name: external Buf module dependencies (`dependencies-not-served`), workspace
check plugins (`check-plugins-not-served`) and remote generators
(`remote-generators-not-served`).
Tools come from the repository's checksum-locked mise pins. Generation runs
without network; provisioning uses the existing proxy-confined fetch path.

A template's `out` may be beneath the Buf workspace, or outside it and inside
the repository; one that leaves the repository is refused. An `out` in a
Component other than the workspace's own (wherever it is) must be consented by
that Component, which says in its catalog file that the workspace's Component
generates it:

```yaml
spec:
  frontseat:
    generated:
      - directory: gen        # relative to this catalog file
        by: component:api     # the Component of the Buf workspace
```

The action still writes nothing outside its project: a template with such
an `out` runs as `buf generate --template buf.gen.<name>.yaml -o
.gen-<name>/<workspace>`, so that `../lib/gen` is written at
`.gen-<name>/lib/gen` in the workspace, and the host places it at `lib/gen`.
A template whose outputs are all beneath the workspace runs as before.

Generated output directories must be at or beneath the root of an existing
Go module, the nearest. The module keeps its handwritten `go.mod`, `go.sum` and source; Go is its sole
coordinate provider. The host excludes authoritative generated copies from
checkout analysis and staging and hands selected worker outputs to Go and its
dependents. Go annotation metadata is generated authority too, while Go input
sets select the Go source. Output files outside declared patterns are refused.
A copy of generated source the checkout holds is kept in step with what
the worker generated: the host compares each produced file within the
declared patterns with the checkout's copy by digest, and a copy that
differs, one that is missing or one the generator no longer produces is a
rewrite; a checkout that holds no copy at all keeps none. The build fails as a rewrite and says which files; `frontseat
build --fix` writes the worker's output over them, through the snapshot.
Nothing asks the checkout's history. `buf format -d --exit-code` is a
check whose findings (`buf/format`) name each file; its fix, `buf format
-w`, runs where the checkout is.

The API specs cover absent/stale generated code, changed/deleted declarations,
lint failures, lock enforcement and this repository's actual protobuf/Connect
API consumed by the client build. Sandbox specs build it from a daemon in a
sandbox. Full integration validation requires the local stack.

Not implemented: external Buf module fetching, generation into a new module
without committed metadata, arbitrary local generator programs, and general
binary artifact providers.

## Options

None. The plugin is listed with nothing set, and an option written for
it is refused by name.

```yaml
# frontseat.yaml
plugins:
  buf: {}
```

## Catalog keys

| Key | Read by | What it does |
|---|---|---|
| `spec.frontseat.generated` | the host | A Component's consent that another generates into a directory of its own, each entry a `directory`, from the catalog file, and `by`, the Component of the Buf workspace. It is needed where a template's `out` is in another Component, as said above, and nowhere else. |
