# Mistakes made in local/

The mistakes made in the local stack (its one container of `local/image`:
the grid, the runner pool, the asset service, the OpenShell gateway and
the control plane; the box a workspace's sandbox runs and its one build,
`local/box`; and the program that brings the stack up and down,
`frontseat-local`), each with the check that stops it. The rules every
change keeps are in the root `AGENTS.md`. Run the check; do not trust that
you would not make the mistake.

| The mistake | The check |
|---|---|
| A grid ran another checkout's build, or kept running after its worktree was removed. | The stack runs the images built from the checkout that started it, which its container is labelled with (`frontseat.dev/checkout`); `mise start` refuses a stack another checkout started (`frontseat-local ready`, `TestAStackAnotherCheckoutStartedIsRefusedBeforeAnythingIsBuilt`), and `mise stop` stops whichever is up. `docker inspect frontseat-local --format '{{index .Config.Labels "frontseat.dev/checkout"}}'` names the checkout. |
| The worker kept its cache in a directory OrbStack holds in memory, sized past what it had, and builds failed with no word of why. | What the stack keeps is on its one volume (`frontseat-local`), and nothing of the machine is mounted; when builds fail together and say nothing, read `docker logs frontseat-local` and `docker exec frontseat-local df` first. |
| A stack or a test ran a box by a tag another checkout had moved (`frontseat-box:local`, `frontseat-box:test`), and failed for every checkout. | Nothing that must run a checkout's box names a shared tag: the stack and the tests run the box by its tag of its content (`frontseat-box:<twelve hex digits of its id>`, `FRONTSEAT_TEST_BOX`, `TestAStackRunsTheImageAndBoxOfItsCheckout`), and the stack's image likewise (`frontseat-local:<…>`, `FRONTSEAT_TEST_LOCAL_IMAGE`). What an image holds is listed before a run is trusted (`docker run --rm --entrypoint ls <image> /opt/frontseat/plugins`); a test that needs an image with no entrypoint is given the workers' own (`testbox.Plain`), and nothing builds one. |
| Each build of the box was an image of its own, so a rebuild moved a tag and the runtime deleted an image a sandbox was starting from. | The same source builds the same image (files of one moment, no build record, every package of the stack's image at its version); build twice and compare `docker inspect --format {{.Id}}` before trusting a tag two processes build. |
| A box was built with the plugins of an earlier build, because the runtime's builder kept a context's files by its directory's name and each file's size and time, which every build gave alike, and a plugin changed by the plugin ABI kept its size. | The context is named by a digest of what it holds (`byContent`, `TestAContextIsNamedByWhatItHolds`), for the box and the stack's image alike, and a spec reads two plugins of one size back from their own images (`TestABoxHoldsThePluginsItWasBuiltWithWhateverABuildBeforeItHeld`); before trusting a box, compare `docker run --rm --entrypoint sha256sum <image> /opt/frontseat/plugins/<name>.wasm` with `dist/plugins`. |
| The workers advertised the architecture the image's builder ran on, as `uname -m` spells it (`x86_64`), which no daemon asks for (`x86-64`): on an Intel machine no action found a worker. Found by review. | The grid's name of an architecture is said once (`local.ISA`), and the builder tells the image it (`ISA`); `docker exec frontseat-local cat /etc/frontseat/isa` is `aarch64` or `x86-64`. |
| The grid's ports were published on every interface, so anyone on the network could have the workers run anything. | Every published port is on `127.0.0.1` (`TestTheContainerIsGivenWhatNestingNeedsAndNothingOfThisMachine`), each where `local/ports` says (`TestTheStacksImageListensWhereThePortsAreSaid`). |
| One `frontseat-action` in the workers' directory was shared by every checkout, whatever box installed it last. | Each form of the confiner is installed under its own name (`/bb/frontseat-action-<form>`, `confine.Install`), never over one that answers, and a spec names its form; the tests install their checkout's own into the stack's container (`testgrid.Confiner`, `box.InstallConfiner`), and the stack's installer installs the one of the box it runs. `docker exec frontseat-local ls /var/lib/frontseat/bb` lists the forms. |
| `frontseat-local init` gave frontseat everything beneath the directories it laid out, recursively, on every start: on a volume used before it took Podman's store, whose files are of frontseat's subordinate ids, and the limits of frontseat's own cgroup. Found by review. | It owns only the directories it makes, and delegates a cgroup as systemd's `Delegate=` does (its directories, `cgroup.procs`, `cgroup.threads`, `cgroup.subtree_control`), never what limits it (`TestInitLaysOutTheStateForWhoKeepsEachPart`, `TestInitGivesFrontseatACgroupSubtreeWithTheControllersTheKernelHas`). |
| A oneshot ran as root and copied and changed modes into a directory frontseat owns, following any link frontseat had planted there. Found by review. | What writes into a user's directory runs as that user (`s6-setuidgid`): the `identity` oneshot is frontseat's. A root oneshot writes only where root alone may. |
| `init` made `/run/user` private to root, and frontseat's Podman could not reach its own runtime directory beneath it. | The directories above a user's runtime directory are open to pass through (`TestInitLaysOutTheStateForWhoKeepsEachPart`). |
| A runner sandbox kept the FUSE mount its slot had when it was made; the worker, started again, mounted the slot anew, and every action in that sandbox failed ("transport endpoint is not connected"). Likewise a sandbox an earlier stack left, its records on the volume, was taken for the slot's. | The pool reads each slot's mount and makes the slot's sandbox anew whenever it changes, deleting one of its id first and waiting until it is gone (`TestASlotMountedAnewHasItsSandboxMadeAgain`, `TestASandboxAnEarlierPoolLeftIsMadeAnew`). |
| A slot was bound at the runner image's working directory, which OpenShell reserves for its own workspace, and every sandbox was refused. | A slot is bound at `/slot`; the image's working directory is its user's own, as OpenShell requires (frontseat-images' buildbarn-runner, its structure test). |
| The driver handed the gateway its mounts as a list of maps, which a protobuf Struct does not hold, and every sandbox was refused. | What is sent is what a Struct holds: `structpb.NewStruct` of it in its test (`TestAHostVolumeIsBoundAsItSays`). |
| Starting Docker Desktop switched this machine's Docker context to it, and every other session's `docker` failed until it was switched back. | After starting or stopping a container runtime, `docker context ls`; switch back to the one others use (`docker context use orbstack`). |
| The control plane asked `docker` what the box image starts with, and the stack's container has only Podman: no workspace could be made. | What a program asks of a container runtime is its flag (`frontseat-local --runtime podman`), never a name it assumes; `TestTheStackMakesAWorkspaceWithNothingStartedByHand` makes one through the stack's own control plane. |
| Podman wrote the stack container's hosts file, and a name of its own for this machine (`host.docker.internal`), into every sandbox: the sandbox resolved the name there, OpenShell's proxy saw an address no DNS answer of its own had given, and refused the connection with no word of why. | `containers.conf` gives a sandbox nothing of Podman's (`base_hosts_file`, `host_containers_internal_ip`) and the gateway says where its names of this machine lead (`host_gateway_ip`, written by `init`, `TestInitSaysWhereASandboxsNamesOfThisMachineLead`); to see why OpenShell refuses, have the sandbox made with `log_level` debug and read the supervisor's `Policy DNS mapped` line. |
| OpenShell takes `host.docker.internal` for its own host gateway, the stack's container, and a sandbox asking for this machine reached the container's loopback. | The gateway's host gateway is this machine, as the runtime names it, where the grid's ports are published too. |
| The pool kept its slots one after another, and one slot whose sandbox would not end held every other for a minute a round, the worker finding no runner meanwhile. | Each slot is kept apart, at once (`TestASlowSlotHoldsUpNoOther`). |
| The gate built the tests' box and never gave it to the stack's Podman, and every sandbox test failed to pull it, once its content differed from the stack's own. | The gate hands its box to the stack (`box.Give`), as `frontseat-local up` does. |
| A sandbox's lookups failed now and then under a full gate ("No address associated with hostname"): each OpenShell supervisor asks its one nameserver once and waits two seconds, and the runtime's resolver (OrbStack's) loses and refuses what many ask of it at once. | The stack's container has its own resolver (Unbound), which its resolv.conf names, and so each supervisor's, keeping and serving answers and asking again (`local/stack` `Resolver`; `TestInitHasTheContainerAskItsOwnResolver`, `TestTheStackBootsAsOneContainer`). Measure a resolver under load as a supervisor asks it (one UDP query, 2 s, no retry, many at once) before blaming what asks. |
